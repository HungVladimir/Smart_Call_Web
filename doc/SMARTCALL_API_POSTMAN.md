### 0.2. Thiết lập Postman trước khi bấm Send
1. **Chứng chỉ HTTPS nội bộ (TLS/CA):** Nếu Wazo hoặc IdP dùng CA nội bộ, vào **Settings → Certificates** thêm file CA `.pem` (khớp `SMARTCALL_TLS_CA_FILE`), hoặc tạm tắt *Enable SSL certificate verification* khi thử trên môi trường lab.
2. **Tắt Auto-Follow Redirects cho API 302:** Với `GET /api/auth/login` và `GET /api/auth/idp-logout/continue`, mở tab **Settings** ngay trên request đó và chuyển **Automatically follow redirects = OFF** để quan sát đúng HTTP `302`, header `Location` và `Set-Cookie`.
3. **Cách lấy phiên Single ID từ trình duyệt đưa vào Postman:**
   - Mở trình duyệt tới `{{smartcall_origin}}/login`, bấm đăng nhập Single ID thành công tới `/calls` (hoặc `/callback`).
   - Mở DevTools (**F12 → Application → Cookies → `http://localhost:8800`**), tìm cookie tên `smartcall_session` (cột Path là `/api/auth`), copy **Value** vào `{{smartcall_session}}` (hoặc add vào Postman **Cookies** cho domain tương ứng với `Path=/api/auth`).
   - Nếu gán thủ công trong từng request bằng header, dùng `Cookie: smartcall_session={{smartcall_session}}` (hoặc thêm cả `smartcall_oidc_state` / `smartcall_logout` khi test bước trung gian). Lưu ý không dùng đồng thời Postman Cookie Jar và header `Cookie` thủ công để tránh gửi trùng cookie.
4. **Quy ước chọn Body trong Postman:** Với mọi API gửi JSON, chọn **Body → raw → JSON** (Postman tự gắn `Content-Type: application/json`). Với API trao đổi OIDC code tới IdP (`token_endpoint`), chọn **Body → x-www-form-urlencoded**.

## 2. API Single ID / OIDC (`{{idp_issuer}}` và Discovery)

FastAPI tại [backend/oidc.py](../backend/oidc.py) chỉ giao tiếp với IdP từ phía server (ngoại trừ browser chuyển hướng sang trang đăng nhập/đăng xuất IdP).

| Method và URL | Mục đích | Cách dùng trong app | Cách test trên Postman |
| --- | --- | --- | --- |
| `GET {{idp_discovery_url}}` (hoặc `{{idp_issuer}}/.well-known/openid-configuration`) | Lấy metadata URL xác thực, token, JWKS và logout | `OidcClient.metadata()` cache 3600s và kiểm tra `issuer` khớp `SMARTCALL_IDP_ISSUER` | **URL:** `{{idp_discovery_url}}`<br>**Headers:** `Accept: application/json`<br>**Kỳ vọng:** `200 OK`. Kiểm tra đủ các endpoint HTTPS: `issuer`, `authorization_endpoint`, `token_endpoint`, `jwks_uri`, `userinfo_endpoint`, `end_session_endpoint`, `claims_supported`. |
| `GET {{authorization_endpoint}}` | Trang đăng nhập SSO doanh nghiệp | Backend dựng URL từ `client_id`, `redirect_uri`, `scope`, `state`, `nonce`, `code_challenge` rồi redirect `302` | **Cách test:** Không bấm Send trực tiếp trên Postman vì có form đăng nhập UI. Mở `GET /api/auth/login` trên Postman (tắt redirect) để đối chiếu chính xác tham số query trong header `Location`, sau đó đăng nhập bằng trình duyệt. |

Dùng để kiểm tra xem IdP có trả nhiều trường hơn ngoài `id_token` không. | **URL:** `{{userinfo_endpoint}}` (lấy từ discovery JSON)<br>**Headers:** `Authorization: Bearer {{idp_access_token}}`, `Accept: application/json`<br>**Kỳ vọng:** `200 OK` trả JSON toàn bộ thuộc tính người dùng theo `scope` đã cấp (`SMARTCALL_IDP_SCOPE`). |

> **Cách kiểm tra toàn bộ tên trường IdP trả về không cần Postman `token_endpoint`:**

## 7. Trình tự kiểm tra nhanh toàn luồng bằng Postman

1. **Xác thực & Single ID:** Gọi `GET /api/health` → kiểm tra `GET {{idp_discovery_url}}` → đăng nhập Single ID trên trình duyệt (nếu cần soi trường mới, bật `SMARTCALL_IDP_LOG_CLAIM_SCHEMA=true` ở backend) → copy cookie `smartcall_session` sang Postman → gọi `GET /api/auth/user_info` (lấy `{{csrf_token}}`) → gọi `POST /api/auth/wazo-session` (lấy `{{wazo_user_token}}` và `{{user_uuid}}`).
2. **Kiểm tra `description` (Bộ phận) & Danh bạ:** Lấy `{{wazo_admin_token}}` nếu test trực tiếp Confd → đối chiếu `GET /api/confd/1.1/users/{{user_uuid}}` xem trường `description` → dùng `{{wazo_user_token}}` gọi `GET /api/dird/0.1/directories/default/sources?backend=wazo` (lấy `{{source_uuid}}`) → test `GET /api/directory/contacts?source={{source_uuid}}` và `GET /api/directory/departments?source={{source_uuid}}` (thử `refresh=true`, `department=...`, `presence=online`).
3. **Nhóm gọi cá nhân:** Gọi `POST /api/call-groups` tạo nhóm 2 thành viên → `PUT /api/call-groups/{{group_id}}` → đổi sang token user khác thử `GET` và `DELETE` để xác nhận cô lập chủ sở hữu (`404`) → dùng đúng token chủ để `DELETE`.
4. **Thoại, Hội nghị & Ghi âm:** Mở 2 máy Web/Android tạo cuộc gọi thật → gọi `GET /api/calld/1.0/users/me/calls` lấy `{{call_id}}` → test `PUT .../record/start` và `.../record/stop` → cúp máy → gọi `GET /api/call-logd/1.0/users/me/cdr` lấy `{{cdr_id}}`, `{{recording_uuid}}` → gọi `GET .../media` kiểm tra file âm thanh.
5. **Đăng xuất & dọn dẹp:** Gọi `POST /api/auth/idp-logout` → gọi `GET /api/auth/idp-logout/continue` (hoặc mở trên browser) → gọi lại `GET /api/auth/user_info` xác nhận `401` → `DELETE /api/auth/0.1/token/{{wazo_admin_token}}` cho token admin tạm đã tạo khi test.
